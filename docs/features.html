What the system does

Guest-facing

Guest booking

Three bookable experiences, each with live availability so nothing can be oversold.

Excursions

Live date/time availability, adult & child pricing, flat-rate or per-guest pricing modes, and a booking cut-off enforced the evening before departure.

Beach chairs

Same-day booking against a specific numbered spot and time slot — no advance cut-off.

Events

Ticket tiers with per-tier pricing and quantity selection for one-off happenings.

Oversell-proof capacity

Row-level database locking holds capacity during checkout, so two simultaneous bookings can never both win the last spot.

Mobile navigation

Hamburger menu with expandable submenus, matching the desktop hover dropdowns.

Find my booking

Self-service lookup by reference code + email, for a guest who's lost their confirmation email.

Restaurant

Dining & reservations

A full restaurant section: browsable menus and a no-payment table request, built into the same system.

Structured menus

Each menu is built from sections and priced items — not a block of text — so pricing lines up cleanly on the page.

Menu descriptions & timings

An overview line and serving hours (e.g. 6:00 PM – 10:00 PM) shown on every menu's card and page.

Embedded reservation form

No linking away — a request-a-table form sits directly on every menu page and the restaurant overview, with a menu-of-interest picker where there's no fixed menu.

No payment, no live count

Purely an enquiry: staff follow up by phone or email to actually confirm the table.

Status workflow

Each request moves New → Contacted → Confirmed or Declined as staff work through it.

Payments

Checkout & confirmation

Three independent payment methods, and a reference scheme that makes every booking easy to talk about on the phone.

Stripe & NMI card payments

Two independent card gateways, each switchable on or off — the guest picks when more than one is enabled.

Offline / bank transfer

Guest sees bank details at checkout; the booking is held pending until staff manually verify and confirm payment.

Human-readable booking codes

Every booking — excursion, chair, event, or table request — gets a code like COCO_EXC_20260904_0007 instead of an opaque ID.

Print & PDF confirmation

Every confirmation page can be printed or downloaded as a branded PDF.

Communication

Emails & notifications

Guests and staff both stay in the loop automatically.

Branded confirmation emails

Styled HTML (with a plain-text fallback) for every booking type, showing full details and payment status.

Admin new-booking alerts

An optional notification address gets emailed the moment any booking or table request comes in.

Offline payment instructions

Guests who choose bank transfer get the account details and a reminder to send their receipt.

Admin panel

Running the property

Everything guest-facing has a matching admin surface to manage it.

Full content management

Excursions, beach chairs, events, restaurant menus, and holiday closures — all editable, including card/header photo uploads.

Booking lists & exports

Search and date-range filters per booking type, with one-click Excel export.

Interactive dashboard calendar

Click any date to jump straight to that day's bookings, filtered exactly to it.

Staff roles

Super Admin, Location Manager, Booking Staff, Finance, and Travel Agent — each with different edit permissions.

System settings

Property name, timezone (with live UTC offset), currency, SMTP, payment gateway keys, and notification addresses — all in one place.

Responsive on any device

A slide-in sidebar on mobile and horizontally-scrolling tables, so the panel is usable from a phone in the field.

Audit log

Every staff action — created, edited, cancelled, marked paid — is recorded with who and when.

Under the hood

Platform & reliability

The details that don't show up in a screenshot but decide whether the system holds up in production.

Timezone-correct cut-offs

Booking cut-offs and "next departure" calculations use the property's own timezone, not the server's.

Graceful payment-form failures

Card validation errors surface immediately, and a safety timeout guarantees checkout never spins forever with no explanation.

Production-hosting ready

Runs on shared cPanel/LiteSpeed hosting — the build and deploy path is tuned for that environment's constraints.
